# Maya Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A floating panda assistant ("Maya") that answers shop questions in Sinhala and English with allowlisted link buttons, launched with the Guided (no-AI) engine, with an AI engine built behind the same interface but OFF.

**Architecture:** A pure guided engine runs in the browser from a cookie-less ISR config (no server call). The widget is a client island in the root layout; its window loads lazily. The AI engine is `POST /api/chat` and returns the same reply shape; any failure falls back to Guided. Admin edits everything at `/admin/chat`.

**Tech Stack:** Next.js 16.4.3 (read `node_modules/next/dist/docs/` before route/layout work), React 19.2, Tailwind v4, Supabase (cookie-less public reads, secret-key writes), Vitest, plain `fetch` for the model (no SDK, no Framer Motion).

**Spec:** `docs/superpowers/specs/2026-11-19-maya-chat-design.md`

## Global Constraints

- Every customer-facing string is bilingual (`{si, en}` / `<L si en />`); admin pages stay English.
- No chat text is stored or logged; only counters. The AI never receives personal data.
- Honest claims: `requires` hides topics/sentences for features that are off; "only N left" only with real low stock; rating shown only with ≥ 5 approved reviews.
- Links come from an allowlist; the AI returns link ids, never URLs. Plain text rendering only.
- Mascot upload: PNG/WebP/JPEG, ≤ 1 MB (1,048,576 bytes), **no SVG**.
- Every admin action starts with `await requireAdmin(...)`; the migration is additive; unreadable config means Maya is not shown (fail closed).
- Defaults when engine/AI is off: `enabled` false, `engine` guided. Default model `claude-haiku-5-5`; env var `ANTHROPIC_API_KEY`; no model prices in code.
- SQL: give the owner a link to the migration file, never paste it; verify afterwards with read-only `list_tables`.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; work on branch `feat/maya-chat`; fast-forward merge to local `main` only, push only when asked.

## Review Focus

1. A Sinhala-only or empty or very long message with no keyword match: the fallback reply, never a throw (Task 3).
2. A `{placeholder}` with no fact (e.g. no WhatsApp number): the sentence is dropped, never `{whatsapp}` or `undefined` on screen (Task 3).
3. A hidden topic still referenced by another topic's `followUps` or by a chip: it must not appear (Task 3).
4. An SVG, a 2 MB file or a wrong content type as a mascot: refused before anything is saved (Task 6).
5. An AI request with 11 messages, a `system` role, an oversized message or an unknown product id: refused or ignored; a daily-cap read error counts as over the cap (Task 8).

### Task 3: Guided engine (`lib/chat-guided.ts`)

**Files:** Create `lib/chat-guided.ts`, `lib/chat-guided.test.ts`.

**Interfaces — Consumes:** Tasks 1–2. **Produces:**
- `normalize(text: string): string` (lowercase, NFC, punctuation to spaces, collapse spaces)
- `visibleTopics(topics: ChatTopic[], features: ChatFacts["features"]): ChatTopic[]` (drops `visible: false` and topics whose `requires` feature is off; sorted by `sortOrder`)
- `matchTopics(text: string, topics: ChatTopic[]): ChatTopic[]` (best first; empty array when no hit; Latin keywords match whole words, Sinhala keywords match as substrings; `text` over 300 chars is cut to 300)
- `fillFacts(template: string, facts: ChatFacts): string` (replaces known `{name}`; a sentence containing an unknown/empty placeholder is removed; money via `formatPrice`)
- `replyForTopic(topic: ChatTopic, topics: ChatTopic[], facts: ChatFacts): ChatReply` (chips = visible `followUps` only, max 4)
- `answerFor(text: string, config: ChatConfig): ChatReply` (one clear winner → its reply; close tie → `chips` of up to 3 titles with a "which one?" text; none → fallback with starter chips and contact links)
- `type PageContext = { kind: "home" | "product" | "cart" | "checkout" | "order" | "other"; productName?: string; source?: string }`; `pageContext(pathname: string, search: URLSearchParams, products: { id: string; name: string }[]): PageContext`; `greetingFor(ctx: PageContext, config: ChatConfig): { text: Bi; chips: { id: string; label: Bi }[] }`.
