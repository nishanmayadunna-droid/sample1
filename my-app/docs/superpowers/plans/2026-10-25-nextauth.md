# Auth (NextAuth / Auth.js v5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add email/password and Google sign-in with `user`/`admin` roles, an `/account` page and an admin-only `/admin` placeholder, without making catalog pages dynamic.

**Architecture:** Auth.js v5 with JWT sessions and no adapter. Users live in a Supabase `public.users` table reached only through a server-only secret-key client. Pure decision logic (validation, Google account linking, callback URL safety) lives in one I/O-free module covered by Vitest; pages enforce access through `requireUser()`/`requireAdmin()`, with `proxy.ts` as an optimistic redirect only.

**Tech Stack:** Next.js 16.2.12 (App Router), React 19.2, `next-auth@5.0.0-beta.32`, `bcryptjs`, `server-only`, `@supabase/supabase-js` 2.118.0, Vitest, Tailwind v4.

**Spec:** `docs/superpowers/specs/2026-10-25-nextauth-design.md`

## Global Constraints

- Read the relevant guide under `node_modules/next/dist/docs/01-app/` before writing Next.js code (project rule). `middleware` is renamed `proxy` in Next 16; `proxy.ts` runs on the Node.js runtime; `searchParams`/`params` are Promises.
- Pin `next-auth` to exactly `5.0.0-beta.32` (no `^`).
- Session strategy: `"jwt"`. No Auth.js adapter.
- The root layout must **not** call `auth()`. `/`, `/products`, `/products/[id]`, `/cart` must stay static/ISR in `npm run build` output.
- `SUPABASE_SECRET_KEY` may be imported only from files that `import "server-only"`.
- `role` values: exactly `'user'` and `'admin'`; default `'user'`.
- Password: 8–72 **bytes** (UTF-8); bcryptjs cost **12**. Name: optional, trimmed, max 100 characters.
- Emails are trimmed and lowercased before every lookup and insert (password and Google paths alike).
- Accounts are never linked automatically.
- UI copy is English and uses the Northbound tokens/classes (`bg-panel`, `text-blaze`, `text-muted`, `border-line`, `.display`, `.eyebrow`, `.measure`); no default Tailwind palette colors.
- Exact user-facing messages (copy verbatim):
  - `This email already has an account.`
  - `Invalid email or password.`
  - `This account uses Google sign-in.`
  - `This email uses a password. Sign in with your password.`
  - `Sign-in failed. Please try again.`
  - `Something went wrong, please try again.`
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `feat/auth`.

## Review Focus

1. **Header stays stale after sign-in/out** — the Header reads the session client-side; after signing in or out it must show the new state without a manual refresh. Covered by doing all sign-in/sign-out through `next-auth/react` with a redirect (full navigation), and manual check 1/8 in Task 7.
2. **Mixed-case or padded email from Google** — `Bob@X.com ` from Google must hit the same row as `bob@x.com` and be rejected if that row is a password account. Test in Task 1 (`resolveGoogleSignIn` normalizes).
3. **Multibyte passwords** — a password of 30 emoji is 30 characters but 120 bytes and must be rejected (bcrypt would silently truncate). Test in Task 1.
4. **Backslash / protocol-relative callback URLs** — `/\evil.com` and `//evil.com` are treated as external by browsers and must fall back to `/account`. Test in Task 1.
5. **Sign-up race on the same email** — two submits at once: the second insert hits the unique constraint (Postgres `23505`) and must show `This email already has an account.`, not the generic error. Handled in Task 2 (`createPasswordUser` returns `"exists"`), checked manually in Task 7.

```ts
import { describe, expect, it } from "vitest";
import { normalizeEmail, validateSignUp, resolveGoogleSignIn, safeCallbackUrl } from "./auth-rules";

const pw = (n: number) => "a".repeat(n);

describe("normalizeEmail", () => {
  it("trims and lowercases", () => expect(normalizeEmail("  Bob@X.COM ")).toBe("bob@x.com"));
});

describe("validateSignUp", () => {
  it("accepts valid input and normalizes", () => {
    expect(validateSignUp({ email: " A@B.co ", password: pw(8), name: "  Ana " }))
      .toEqual({ ok: true, value: { email: "a@b.co", password: pw(8), name: "Ana" } });
  });
  it("turns a blank name into null", () => {
    const r = validateSignUp({ email: "a@b.co", password: pw(8), name: "   " });
    expect(r.ok && r.value.name).toBeNull();
  });
  it.each(["", "no-at", "a@", "@b.co", "a b@c.co"])("rejects email %j", (email) => {
    const r = validateSignUp({ email, password: pw(8), name: "" });
    expect(r.ok).toBe(false);
    expect(!r.ok && r.errors.email).toBeTruthy();
  });
  it.each([[7, false], [8, true], [72, true], [73, false]])("password of %i chars ok=%s", (n, ok) => {
    expect(validateSignUp({ email: "a@b.co", password: pw(n), name: "" }).ok).toBe(ok);
  });
  it("rejects a password over 72 bytes even under 72 chars", () => {
    const r = validateSignUp({ email: "a@b.co", password: "😀".repeat(30), name: "" });
    expect(!r.ok && r.errors.password).toBeTruthy();
  });
  it("rejects a name over 100 chars", () => {
    const r = validateSignUp({ email: "a@b.co", password: pw(8), name: "n".repeat(101) });
    expect(!r.ok && r.errors.name).toBeTruthy();
  });
  it("rejects non-string fields", () => {
    expect(validateSignUp({ email: null, password: 5, name: undefined }).ok).toBe(false);
  });
});

describe("resolveGoogleSignIn", () => {
  const profile = { email: "Bob@X.com ", emailVerified: true, googleId: "g1" };
  it("rejects an unverified email", () =>
    expect(resolveGoogleSignIn(null, null, { ...profile, emailVerified: false }))
      .toEqual({ action: "reject", reason: "unverified" }));
  it("allows a known google id", () =>
    expect(resolveGoogleSignIn({ googleId: "g1", hasPassword: false }, null, profile)).toEqual({ action: "allow" }));
  it("rejects when the email belongs to a password account", () =>
    expect(resolveGoogleSignIn(null, { googleId: null, hasPassword: true }, profile))
      .toEqual({ action: "reject", reason: "password_account" }));
  it("creates with a normalized email when nobody has it", () =>
    expect(resolveGoogleSignIn(null, null, profile)).toEqual({ action: "create", email: "bob@x.com" }));
});

describe("safeCallbackUrl", () => {
  it.each([["/cart", "/cart"], ["/products/x?y=1", "/products/x?y=1"]])("keeps %s", (u, e) =>
    expect(safeCallbackUrl(u)).toBe(e));
  it.each(["//evil.com", "/\\evil.com", "https://evil.com", "evil", "", null, undefined])("rejects %j", (u) =>
    expect(safeCallbackUrl(u)).toBe("/account"));
  it("uses a custom fallback", () => expect(safeCallbackUrl(null, "/")).toBe("/"));
});
```

- [ ] **Step 2: Implement `auth.ts`**

- `session: { strategy: "jwt" }`.
- Credentials `authorize(credentials)`: `findUserByEmail`; no user → `null`; user with no `passwordHash` → `throw new GoogleAccountError()`; `verifyPassword` false → `null`; else return `{ id, email, name, image, role }`.
- `callbacks.signIn({ account, profile })`: for `account.provider === "google"`, look up by `account.providerAccountId` and by `profile.email`, call `resolveGoogleSignIn(toExistingAccount(a), toExistingAccount(b), { email: profile.email, emailVerified: profile.email_verified === true, googleId: account.providerAccountId })`. `create` → `createGoogleUser`, return `true`; `allow` → `true`; reject `password_account` → return `"/signin?error=OAuthAccountNotLinked"`; reject `unverified` → `false`. Credentials → `true`.
- `callbacks.jwt({ token, user, account })`: on sign-in with Google, set `token.id`/`token.role` from `findUserByGoogleId(account.providerAccountId)`; with credentials, from `user`. Otherwise return `token` unchanged (no DB call per request).
- `callbacks.session`: copy `token.id`, `token.role` onto `session.user`.

- [ ] **Step 3: Route handler**

`app/api/auth/[...nextauth]/route.ts`: `import { handlers } from "@/auth"; export const { GET, POST } = handlers;`

- [ ] **Step 4: `proxy.ts`**

### Task 5: Sign-in page and sign-up action

**Files:**
- Create: `app/signin/page.tsx`, `app/signin/actions.ts`, `app/signin/SignInForm.tsx`

**Interfaces:**
- Consumes: `validateSignUp`, `safeCallbackUrl`, `createPasswordUser`, `auth`
- Produces:
  - `actions.ts` (`"use server"`): `export type SignUpState = { ok: boolean; errors: SignUpErrors; formError: string | null }`; `export async function signUpAction(prev: SignUpState, formData: FormData): Promise<SignUpState>` — `validateSignUp`; `createPasswordUser`; `"exists"` → `errors.email = "This email already has an account."`; thrown error → `formError = "Something went wrong, please try again."`; success → `{ ok: true, errors: {}, formError: null }`
  - `SignInForm` props: `{ callbackUrl: string; error: string | null }`

Design note: the spec has the Server Action call `signIn`; instead the client calls `signIn` from `next-auth/react` after the action returns `ok`, so the browser does a full navigation and the Header's client session is fresh (Review Focus 1). Behavior seen by the user is the same.

- [ ] **Step 1: `page.tsx`**

`searchParams: Promise<{ callbackUrl?: string; error?: string }>`. If `await auth()` has a user → `redirect(safeCallbackUrl(callbackUrl))`. Otherwise render `<SignInForm callbackUrl={safeCallbackUrl(callbackUrl)} error={error ?? null} />`. `metadata.title = "Sign in"`.

- [ ] **Step 2: `actions.ts`**

- [ ] **Step 3: `SignInForm.tsx`** (`"use client"`)

- Tabs "Sign in" / "Create account"; "Continue with Google" above both → `signIn("google", { redirectTo: callbackUrl })`.
- Sign in submit: `const r = await signIn("credentials", { email, password, redirect: false })`. `r.code === "google_account"` → `This account uses Google sign-in.`; other `r.error` → `Invalid email or password.`; success → `window.location.assign(callbackUrl)`.
- Create account: `useActionState(signUpAction, initial)`; field errors under each input; when `state.ok`, call credentials `signIn` with the submitted email/password as above.
- `error` prop mapping: `OAuthAccountNotLinked` → `This email uses a password. Sign in with your password.`; `CredentialsSignin` → `Invalid email or password.`; any other non-null → `Sign-in failed. Please try again.`
- Inputs: `type="email" autoComplete="email"`, `type="password"` with `autoComplete` `current-password` / `new-password`, `name` field optional.
