# Sinhala / English and the Marketplace Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the shop bilingual (සිං / EN, admin-controlled) and give it a marketplace shell: promise strip, search header with deal links, cart drawer, full footer, admin-edited promises.

**Architecture:** Both languages are rendered into the HTML and CSS hides the inactive one (`html[data-lang]`); an inline `<head>` script picks the language from the `nb_lang` cookie before first paint, so no page reads cookies and catalog pages stay static/ISR. The root layout reads products, categories, promises and store settings with the cookie-less catalog client and hands them to client components (header, search, drawer). Money and filtering live in pure, tested modules shared by every view.

**Tech Stack:** Next.js 16.4 App Router, React 19.2, Tailwind v4 tokens, Supabase (Postgres + RLS), Auth.js v5, Vitest 4.

**Spec:** `docs/superpowers/specs/2026-11-03-i18n-and-shell-design.md`

## Global Constraints

- Prerequisite: `feat/categories` is merged into `main` and `main` is merged into `feat/i18n-shell` before Task 1 (`getCategories`, `Category`, `productsInCategory`, `resolveCategoryParam`, `AdminTabs` come from it).
- Read the relevant guide under `node_modules/next/dist/docs/` before writing Next.js code; for the boot script follow `01-app/02-guides/preventing-flash-before-hydration.md` (the `InlineScript` helper with the `text/javascript` / `text/plain` type switch and `suppressHydrationWarning`).
- No `cookies()`, `headers()` or `auth()` in the root layout or catalog pages; `/`, `/products/[id]`, `/cart` must still build as static/ISR.
- Language cookie: `nb_lang`, values `si` | `en`, `Path=/; Max-Age=31536000; SameSite=Lax`. Default language `si`, `bilingual` on.
- Translated: every customer-facing UI string. English only: admin pages, product names/descriptions, category names, `<title>`/meta description.
- Prices only through `formatPrice` / `formatPriceWhole`; charge `effectivePrice`.
- Every admin Server Action starts with `await requireAdmin(...)`; storefront writes end with `revalidatePath("/", "layout")`.
- Every new `public` table has RLS on; writes only through `lib/supabase/admin.ts`.
- Only real data: no invented ratings, sold counts, stock or urgency.
- Use the design tokens (`bg-panel`, `text-blaze`, …), not default palette colours.
- Admin forms use the existing `onSubmit` + `startTransition` pattern.
- Sinhala copy is drafted here and reviewed by the owner before merge.

## Review Focus

1. A tampered or stale cookie (`nb_lang=fr`, empty, or `si` while `bilingual` is off) must give the default language — tested in Task 2.
2. Toggling the language must also update attribute text (`tr()` placeholders, `aria-label`s) in already-mounted client components, and survive soft navigation — tested in Task 3 (store notifies subscribers) and checked in the browser in Task 12.
3. A cart holding a product that was hidden or deleted must neither show nor be charged in the drawer or `/cart` — tested in Task 7.
4. Search text with regex characters, extra spaces or mixed case (`"  TEE (  "`) must not throw and must match by words — tested in Task 6.
5. Editing a promise that is already visible while 3 are visible must be allowed; making a 4th visible must be refused — tested in Task 11.

  it("uses a valid cookie", () => expect(resolveLang("en", on)).toBe("en"));
  it("falls back to the default for missing, empty or unknown values", () => {

    new Function("document", langBootScript(settings))({ cookie, documentElement: el });
    return el;

  it("agrees with resolveLang", () => {

      for (const cookie of ["", "nb_lang=en", "nb_lang=si", "nb_lang=fr"]) {
        const el = run(settings, cookie);
        const want = resolveLang(readLangCookie(cookie), settings);
        expect([el.lang, el.dataset.lang]).toEqual([want, want]);
      }
  });
  it("does not throw when document access fails", () =>
    expect(() => new Function("document", langBootScript(DEFAULT_LANG_SETTINGS))(null)).not.toThrow());
