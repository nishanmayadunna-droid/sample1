# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Critical: this is not the Next.js in your training data

This project runs **Next.js 16.2.12** with **React 19.2**. APIs, conventions, and file structure may differ from what you remember. **Before writing any Next.js code, read the relevant guide under `node_modules/next/dist/docs/`** (the App Router docs live in `01-app/`) and heed any deprecation notices. Do not rely on remembered Next.js APIs.

## Commands

```bash
npm run dev     # start the dev server at http://localhost:3000
npm run build   # production build
npm run start   # serve the production build
npm run lint    # ESLint (flat config via eslint-config-next)
```

There is no test runner configured in this project.

## Architecture

This is a **client-side demo storefront** (apparel). No payments or auth. The product catalog lives in Supabase (see below); the cart lives in the browser.

- **App Router** (`app/`). Root layout `app/layout.tsx` wires the fonts via `next/font/google` (Geist sans/mono + Anton display → `--font-geist-*`, `--font-anton`), sets the "Northbound" title template, renders the `AnnouncementBar` + persistent `Header`/footer, and imports `app/globals.css`. Routes: `/` (merchandising home — hero, shop-by-category tiles, flash sale, featured, promise strip, newsletter), `/products` (catalog, filtered by `?category=`), `/products/[id]` (detail; statically generated via `generateStaticParams`), `/cart`.
- **Product data** lives in the Supabase `public.products` table and is split across two modules. `lib/products.ts` holds the `Product` type, `CATEGORIES`, and pure helpers (`formatPrice`, `effectivePrice`, `discountPercent`); it's safe in client components. `lib/catalog.ts` is server-only and does the async reads (`getAllProducts`, `getProduct`, `getProductsByCategory`, each wrapped in React `cache()`). It maps snake_case rows (`sale_price`, `material`/`construction`/`origin`, `image_url`) onto the camelCase `Product` shape. It uses a **cookie-less** supabase-js client on purpose, so catalog pages stay static/ISR (`export const revalidate = 60` on `/`, `/cart`, `/products/[id]`); don't switch it to `lib/supabase/server.ts`, which calls `cookies()` and would make every route dynamic. Client components never fetch products: server pages pass them down (e.g. `/cart` passes the full catalog to `CartView`, which computes the subtotal; the cart store holds only `{id, size, quantity}`). **Prices are stored in cents** (integers); render them through `formatPrice`, never with raw math. Sale items carry an optional `salePrice` — always charge/display `effectivePrice(product)` (falls back to `price`) and it's what the cart subtotal uses; `discountPercent()` drives the sale badges. Product photos are in the public Storage bucket `product-images` as `<product id>.jpg` (placeholder photos from picsum.photos, uploaded by `scripts/upload-product-images.mjs`). `app/components/ProductImage.tsx` renders them with `next/image` over a `swatch` gradient, which also serves as the fallback when `imageUrl` is null; pass `sizes` to match the slot and `preload` for above-the-fold images (`priority` is deprecated in Next 16). `next.config.ts` allows `<NEXT_PUBLIC_SUPABASE_URL>/storage/v1/object/public/**` in `images.remotePatterns`.
- **The flash-sale countdown** (`app/components/FlashCountdown.tsx`) is a client component; it counts to local midnight and, like the cart, uses a `useSyncExternalStore`-based `useHydrated()` flag so the live digits don't cause an SSR/client mismatch. Its `setState` lives inside the interval callback, not the effect body, to satisfy `react-hooks/set-state-in-effect`.
- **Cart state** is in `app/context/CartContext.tsx`. Despite the name it is **not** React Context/a provider — it's a module-level store persisted to `localStorage`, exposed through the `useCart()` hook built on `useSyncExternalStore` (chosen so the React 19 `react-hooks/set-state-in-effect` lint rule stays satisfied, and for hydration + cross-tab safety). Consumers gate cart-dependent UI on the `hydrated` flag to avoid SSR/client mismatch. Mutations (`addItem`/`removeItem`/`setQuantity`/`clear`) are plain exported functions.
- **Server vs client**: pages/most components are Server Components. Only interactive pieces carry `"use client"` — `Header`, `ProductPurchase` (size selection + add-to-cart), `CartView`, `FlashCountdown`, `Newsletter` (client-side validation only; sends nothing), and the cart store.
- **Styling** is **Tailwind CSS v4** via PostCSS (`postcss.config.mjs` → `@tailwindcss/postcss`); no `tailwind.config.js`. All design tokens live in `app/globals.css`: raw CSS variables on `:root` (with a `prefers-color-scheme: dark` override) are mapped in `@theme inline` to the Tailwind color names `bg`, `surface`, `ink`, `muted`, `line`, `blaze` (the single orange accent), `panel`, `panelink`, `panelmuted` — use those (`bg-panel`, `text-blaze`, …), not default palette colors. The same file defines the brand's custom classes: `.display` (Anton, uppercase headings), `.eyebrow` (mono tracked-out spec label), `.measure` (ruler-tick rule), and `.rise` (hero load animation, disabled under reduced motion).
- **Supabase** (project `sample1`, ref `dtytkwxlpvkervhkhcpu`) is used for Database and Storage. Env vars `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (plus server-only `SUPABASE_SECRET_KEY`, used only by scripts) live in `.env.local` (git-ignored). Schema changes are recorded in `supabase/migrations/` with filenames matching the remote migration versions; there's no local Supabase CLI/stack, so migrations are applied to the remote project (via MCP `apply_migration`) and the same SQL is saved there. `products` is read-only to clients: RLS on, one public SELECT policy, no write grants. Edit catalog data in the dashboard or with the secret key. Use `lib/supabase/server.ts` (`await createClient()`, per request) in Server Components/Actions/Route Handlers and `lib/supabase/client.ts` in client components. Only the publishable key may be `NEXT_PUBLIC_`; every table in `public` needs RLS. There is no auth or session-refresh `proxy.ts` yet; add one when auth is introduced.
- **TypeScript** path alias `@/*` maps to the project root (e.g. `@/lib/products`).
- **Agent skills** are vendored twice — `.claude/skills/` and `.agents/skills/` (tracked by `skills-lock.json`) — and are not part of the app. `AGENTS.md` carries the same "read the bundled Next.js docs first" rule as above.
